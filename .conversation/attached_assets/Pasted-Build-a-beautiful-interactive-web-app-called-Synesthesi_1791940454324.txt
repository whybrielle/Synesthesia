Build a beautiful, interactive web app called **“Synesthesia”** that transforms photos from a user's photo library into simple melodies. The core idea is to turn visual memories into sound, allowing users to see and hear their photos in a completely new way.

## 1. Core User Experience

Create a smooth, intuitive experience with three main steps:

1. **Upload a photo:** Users can select an image from their device's photo library using an upload button or drag-and-drop area. Support JPG, PNG, and WebP.
2. **Generate a melody:** Analyze the uploaded image and convert its visual properties into a short, pleasant musical composition.
3. **Save to gallery:** Let users save the original photo alongside its generated melody so they can revisit and replay it anytime.

The experience should feel magical but simple. A user should be able to upload a photo and hear its melody within seconds.

## 2. Image-to-Music Engine

Implement a real, working image-to-music algorithm. Do not use placeholder audio or randomly generated melodies unrelated to the image.

Extract visual features from the uploaded image directly in the browser using the HTML Canvas API:

- **Average color:** Map the image's dominant colors to musical keys or tonal moods.
- **Brightness:** Use the overall brightness to influence pitch range and note intensity.
- **Color variation:** Use color diversity to determine how complex or varied the melody is.
- **Image composition:** Sample colors from left to right across the image and translate them into a sequence of musical notes.
- **Visual texture:** Use local color differences to influence note duration and rhythm.

Translate these features into a short melody of approximately 8–16 notes. Quantize notes to a pleasant musical scale, such as C major, A minor, or a pentatonic scale, to ensure the output sounds intentional and harmonious.

Use the **Web Audio API** to synthesize the melody directly in the browser. Use soft piano, marimba, or bell-like synthesized tones with gentle envelopes and optional reverb. Avoid harsh or random-sounding audio.

The same image and settings should consistently produce the same melody. Make the mapping deterministic.

## 3. Music Player

After a melody is generated, show an elegant audio player featuring:

- Play and pause controls.
- A replay button.
- A progress indicator or animated playhead.
- The melody's duration.
- A simple visual representation of the notes, such as a piano roll or animated waveform.
- A volume control.
- A button to regenerate the melody with a different musical interpretation.

Include a toggle to switch between a few sound presets, such as Piano, Music Box, and Soft Synth.

Allow users to download the melody as a WAV audio file so they can listen to it outside the website. Generate a real audio file rather than just saving the melody's note data.

## 4. Personal Gallery

Create a gallery where users can save and revisit their photo-melody creations.

Each gallery card should include:
- The uploaded photo as a thumbnail.
- The creation's title, either user-defined or automatically generated.
- A play button to hear its corresponding melody.
- The creation date.
- A button to open the full creation.
- Options to rename or delete the creation.
- An option to download the image and melody.

When a user saves a creation, persist both the image and its associated musical note sequence and settings. Use IndexedDB for browser-based local storage so saved creations remain available after refreshing or reopening the website.

The gallery should display saved creations in a clean, responsive grid. Include an empty state that encourages the user to upload their first photo.

Users should be able to click any gallery card to reopen the photo and replay its exact original melody.

Do not require an account or upload users' private photos to a server. Keep all image analysis, audio generation, and gallery storage on the user's device.

## 5. Visual Design

Use a polished, contemporary visual style inspired by creative tools, digital art galleries, and music production software.

**Design direction:**
- Background: warm off-white or deep charcoal, with subtle gradients.
- Accent colors: soft lavender, electric blue, and muted coral.
- Typography: modern sans-serif fonts with strong visual hierarchy.
- Cards: rounded corners, subtle shadows, and generous whitespace.
- Animations: smooth transitions, gently pulsing visual elements, and motion that responds to music playback.
- Layout: spacious, uncluttered, and focused on the uploaded image.

Make the uploaded image the visual centerpiece. When the melody plays, animate a series of small glowing dots or musical bars that correspond to the notes being played.

Avoid excessive gradients, cluttered dashboards, or generic SaaS-style layouts. The product should feel like a small creative studio.

## 6. Pages and Layout

### Home / Create Page
- A compelling hero headline: “Every picture has a sound.”
- A short subtitle explaining how photos become melodies.
- A prominent upload area with a photo library button.
- A preview of the selected image.
- A “Create My Melody” button.
- A generated music player and note visualization.
- A “Save to Gallery” button.

### Gallery Page
- A grid of all saved photo-melody creations.
- Search or filter functionality for saved creations.
- Sorting by newest or oldest.
- Playback controls on each card.
- A clear button to start a new creation.

### Creation Detail View
- Large image preview.
- Melody player and note visualization.
- Creation title and date.
- Sound preset selection.
- Download image and audio buttons.
- Rename and delete actions.

Use a simple top navigation bar with the app name, “Create,” and “My Gallery.”

## 7. Technical Requirements

Use a modern web stack compatible with Replit:
- React with TypeScript.
- Vite for the development server and build tooling.
- Tailwind CSS for styling.
- Web Audio API for real-time melody synthesis.
- HTML Canvas for extracting image features.
- IndexedDB for persistent local storage.
- Lucide icons for interface elements.

Organize the code into reusable components, including:
- `ImageUploader`
- `ImageAnalyzer`
- `MelodyGenerator`
- `AudioPlayer`
- `NoteVisualizer`
- `GalleryGrid`
- `GalleryCard`
- `CreationDetail`

Handle invalid image files, large uploads, browser storage limits, and audio playback errors gracefully. Include loading and generation states, keyboard-accessible controls, responsive mobile layouts, and helpful error messages.

Do not require paid APIs, API keys, external AI services, or a backend for the core functionality.

## 8. Important Implementation Details

- Build a fully functional application, not just a visual mockup.
- Ensure the generated notes are derived from the actual uploaded image's visual features.
- Store enough information to reproduce the exact melody when a saved creation is reopened.
- Make sure audio playback works after navigating away from a creation and returning to it.
- Export actual playable WAV files.
- Ensure all gallery actions, upload controls, and audio controls work.
- Test the entire flow: upload a photo, generate a melody, play it, save it, refresh the page, reopen the gallery, replay the melody, and download the audio.
- Keep the experience fast, intuitive, and enjoyable on both desktop and mobile.

Start by implementing the complete core experience, including image analysis, deterministic melody generation, audio playback, and persistent gallery storage. Prioritize working functionality over decorative features.
